# The mental-health *subforms* stay: triage.xml embeds
# pih/subforms/mental-health-phq2.xml.
#
# Two different families are called "outpatient" in the stock config and both are
# excluded, because both surface under near-identical names in the form list:
#
#   * outpatient-initial / outpatient-followup -> forms "Outpatient Initial" /
#     "Outpatient Followup" on encounter types "PHU360 Outpatient Initial" /
#     "PHU360 Outpatient Followup".
#   * primary-care-{adult,peds}-{initial,followup} -> forms "Outpatient Intake
#     (Adult)" / "Outpatient Intake (Peds)" / "Outpatient Followup (Adult)" /
#     "Outpatient Followup (Peds)" on encounter types "Primary Care Adult Initial
#     Consult", "Primary Care Adult Followup Consult", "Primary Care Pediatric
#     Initial Consult", "Primary Care Pediatric Followup Consult".
#
# CONSEQUENCE: both register reports used to name these types. above-five-patient-list
# named the two PHU360 Outpatient types and now names "Visit Note", the type its
# register form is attached to. under-five-register named 14 service types because
# the form did not exist; it now names the single "Under Five IMNCI" type that
# underFiveIMNCIRegister.xml is attached to. So retiring these encounter types no
# longer narrows either register report - it only stops the visit UI offering the
# forms, which is what it was for.

# rows are removed outright rather than retired: each program is declared ONLY in

# to go with them, in programworkflows/programworkflows_retired.csv:

# is the only lever - there is nothing in the repo to delete.

# The three registers that survive (motherAndNeonateRegister, deliveryRegister,
# familyPlanningRegister) are tracked delta files and are NOT on this list. They
# are registers that record what a visit was, and a PHU360 visit note still
# records a delivery, a family planning encounter or an ANC contact. Deleting the
# clinical forms that capture a service means the register has nothing to summarise.

# Newborn Initial/Assessment/Daily Progress/Discharge/NICU Triage, Family Planning
# Initial/Followup, Maternal Discharge/Death, Labor and Delivery Summary). With
# no form left to create them, nothing can ever write those encounters, so all four
# are removed from the report catalog rather than left to report a permanent 0.
# The 7 remaining report types read encounter types that surviving forms produce.
#
# htmlforms/retired/ is emptied too. It exists so pihcore does not recreate an old
# (name, version) with a different formUuid than the row it left behind; with every
# form in it also excluded there is nothing left for it to protect.
